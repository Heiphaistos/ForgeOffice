# Plan d'implémentation : Base de données (parité Access)

Date : 2026-11-05. Source : `docs/parite/ACCESS.md` (989 entrées, identifiants `AC-xxx`). Aucun code n'a été modifié par l'audit.

## 1. Où se situe le travail

| Couche | Dossier | État |
|---|---|---|
| Moteur | `crates/forge-base` | Riche : 101 tests, index multi-champs, sous-formulaires, états multi-niveaux, requêtes éditables, import `.mdb`/`.accdb`. Manque surtout : opérateur `&`, fonctions de domaine, fonctions texte/maths/financières, regroupement par intervalle, événements de macro, pièces jointes (API de fichiers), chiffrement, tables liées, journal |
| Pont Tauri | `apps/desktop/src-tauri/src/base_cmds.rs` | 5 fonctions du moteur ne sont pas exposées (index, sous-formulaire, requête éditable, import Access, exécution d'état multi-niveaux). Un `Op` par fonction, plus un test dans le scénario rejoué |
| Interface | `packages/access` | Écart principal : menus contextuels (4 contre plus de 100), concepteur de formulaires/états sans sélection multiple ni propriétés ni événements, aucun générateur d'expressions, aucun assistant, aucun annuler/rétablir, ruban Accueil réduit |

Règles communes à tous les lots :

- Un lot = un ensemble de fichiers **disjoint** des autres lots. Les fichiers partagés (`App.tsx` 627 lignes, `ribbon.tsx`, `strings.ts` 558 lignes, `types.ts`, `db.ts`, `access.css`) ne sont modifiés que par le lot 0 (câblage) ; chaque autre lot livre de **nouveaux** fichiers (`strings-<lot>.ts`, `ribbon-<lot>.tsx`, `components/<zone>/…`) et une seule ligne d'enregistrement dans un registre créé par le lot 0 (`registry.ts` : onglets de ruban, menus contextuels, raccourcis, dialogues).
- Fichier : 800 lignes visées, 1000 maximum (`Datasheet.tsx` 579, `QueryDesign.tsx` 436 et `App.tsx` 627 doivent être scindés avant d'ajouter des fonctions).
- Tout texte visible dans un `strings-*.ts` français. Tests : `node --test packages/access/tests/*.test.ts` pour la logique sans DOM ; pour le moteur `cargo test` ; le scénario `tests/scenario.ts --write` doit être régénéré quand les opérations changent.
- Vérification visuelle obligatoire (exigence du propriétaire) : banc `?app=access`, captures regardées, **et gestes réels** (clic droit, glisser, sélection au lasso) comparés à Access.

## 5. Ordre recommandé

1. **Lot 0** (1 à 2 jours) : sans lui, 9 entrées P1 restent bloquées et les lots touchent tous `App.tsx`.
2. En parallèle : **lots 1, 2, 7 (moteur), 9, 13** (aucune dépendance entre eux), puis **lots 3 et 4** ensemble (3 = interaction, 4 = modèle de propriétés ; le propriétaire de `types.ts` est le lot 4).
3. Ensuite **lots 5, 6, 8, 10, 11** (dépendent de 3/4 et du lot 0), puis **12 et 14** qui assemblent.
4. Lots moteur M1 à M6 au fil de l'eau ; M1 et M2 avant la sortie publique.

Critère de sortie « parité visible » (à la demande du propriétaire) : menus contextuels de la feuille de données, du volet, des onglets, des contrôles et des sections conformes à l'annexe A d'`ACCESS.md` ; mini-barre/ruban Format utilisable sur un contrôle sélectionné ; objets de formulaire et d'état sélectionnables à plusieurs, déplaçables, alignables ; feuille de propriétés ; générateur d'expressions ; Annuler/Rétablir.
